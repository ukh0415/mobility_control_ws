# 플랫폼별 프로젝트 폴더 재구성

## 발생 시각과 환경

- 시각: 2026-09-02 16:27:35 KST
- 환경: Windows 프로젝트 워크스페이스
- 기준 브랜치: `main`에서 분기한 `chore/reorganize-workspace`

## 변경 목적

최상위 폴더 이름만으로 대상 플랫폼을 식별할 수 있도록 STM32와 ESP32 프로젝트를 플랫폼별 디렉터리로 재구성했다.

## 변경 전

```text
mobility/
Arduino/esp32_i2c_master/
```

## 변경 후

```text
stm32/mobility/
esp32/esp32_i2c_master/
```

STM32CubeIDE 내부 프로젝트 이름 `mobility`와 Arduino 스케치 폴더 이름 `esp32_i2c_master`는 유지했다.

## 함께 변경한 항목

- `AGENTS.md` 기준 경로
- `README.md` 프로젝트 구조와 실행 경로
- `.gitignore`의 ESP32 빌드 결과 제외 경로
- 기존 운영 문서의 현재 프로젝트 경로

## 검증 결과

- `stm32/mobility/.project` 존재 확인
- `stm32/mobility/mobility.ioc` 존재 확인
- `esp32/esp32_i2c_master/esp32_i2c_master.ino` 존재 확인
- STM32 및 ESP32 소스 내용은 폴더 이동 과정에서 변경하지 않음

## IDE 재등록 방법

STM32CubeIDE에서 기존 프로젝트가 이전 위치를 가리키면 IDE의 프로젝트 등록만 제거한다. 이때 `Delete project contents on disk`는 선택하지 않는다. 이후 `File → Import → General → Existing Projects into Workspace`에서 `stm32/mobility`를 선택한다.

Arduino IDE에서는 기존 탭을 닫고 `esp32/esp32_i2c_master/esp32_i2c_master.ino`를 다시 연다.

## 남은 위험과 후속 작업

- IDE가 열린 상태에서 이동되었다면 이전 탭이나 프로젝트 항목이 유효하지 않을 수 있다.
- STM32CubeIDE 재등록 후 Clean 및 Build가 필요하다.
- Arduino IDE에서는 새 경로에서 최초 빌드 시 빌드 캐시가 다시 생성될 수 있다.
- 실제 펌웨어 빌드와 하드웨어 플래시는 이번 폴더 재구성 작업에서 수행하지 않았다.
