# 2번 모터 엔코더 추가

## 발생 시각과 환경

- 시각: 2026-09-04 16:07:12 KST
- 브랜치: `jaehyun`
- 대상: STM32F103C8Tx 한 모듈, ESP32 I2C 마스터

## 사용한 코드 버전 또는 Git 커밋

- 기준 커밋: `e662e53`
- 변경 중인 작업 트리에서 CubeMX 코드 재생성 후 기능 추가

## 증상

모터 1은 PA4/PA5 엔코더 값이 상태에 표시되지만, 모터 2를 `j`/`l`로
구동할 때 PB3/PB5 엔코더 값은 읽거나 전송하지 못했다.

## 재현 절차

1. PC 클라이언트에서 `j` 또는 `l`을 입력한다.
2. 모터 2가 회전하는 것을 확인한다.
3. ESP32 상태 출력에 모터 1 값 하나만 표시되는 것을 확인한다.

## 기대 동작

모터 1과 모터 2의 원시 엔코더 카운트가 독립적으로 표시되어야 한다.

## 조사 내용과 측정값

- 기존 GPIO/EXTI 구현은 PA4 상승 에지와 PA5 방향 입력만 처리했다.
- PB3/PB5 배선 계획은 있었지만 CubeMX 핀과 EXTI3가 설정되지 않았다.
- 기존 I2C 상태 패킷은 `mode + int16`의 3바이트여서 카운트 하나만
  전송할 수 있었다.

## 원인

모터 2 엔코더의 GPIO, EXTI 콜백, 별도 카운터 및 상태 패킷 필드가
구현되지 않았다.

## 해결 또는 임시 조치

- PB3을 `MOTOR2_ENC_A`/EXTI3 상승 에지로 설정했다.
- PB5를 `MOTOR2_ENC_B`/GPIO 입력으로 설정했다.
- EXTI3 NVIC 우선순위를 `5/0`으로 설정했다.
- STM32에 `motor2EncoderCount`를 추가했다.
- 진단 상태 패킷을 3바이트에서 5바이트로 확장했다.
- ESP32가 두 개의 `int16` 원시 카운트를 읽어 `enc1`, `enc2`로 출력하도록
  변경했다.

## 검증 결과

- CubeMX 생성 결과에서 PB3/PB5 GPIO와 EXTI3 핸들러 생성을 확인했다.
- STM32와 ESP32의 I2C 상태 길이가 모두 5바이트인지 정적으로 확인했다.
- 로컬 환경에서 STM32 및 Arduino 컴파일 도구를 찾지 못해 컴파일과
  실제 보드 시험은 아직 수행하지 않았다.

## 남은 위험과 후속 작업

- STM32와 ESP32 펌웨어를 반드시 함께 갱신해야 한다.
- `j`에서 `enc2`가 변하고 `i`에서 `enc1`이 변하는지 실기로 확인한다.
- 회전 방향과 카운트 부호가 반대면 모터 2 콜백의 증가/감소를 교환한다.
- 엔코더 PPR과 감속비가 확정되면 원시 카운트를 실제 각도로 환산한다.
- 현재 `int16` 전송을 위해 32000 카운트 단위로 순환하므로 장거리 누적
  위치가 필요하면 상태 패킷을 `int32`로 확장한다.
