# 20260917_131141 CE 오류코드 상세 가이드

## 1. 문서 목적

STM32의 모터2 위치 제어와 모터3 클러치 조그 시험에서 사용하는 `CE_*` 오류 코드의
숫자, 발생 조건, 의미와 확인 순서를 한 문서에서 찾을 수 있게 정리한다. 기준 소스는
`stm32/mobility/Core/Inc/carrier_test.h`이다.

현재 주요 시험 설정은 다음과 같다.

```c
#define CARRIER_MOVE_PWM_PERCENT 70
#define CARRIER_COUNT_TOLERANCE 3
#define CARRIER_SETTLE_MS 300U
#define CARRIER_MOVE_TIMEOUT_MS 10000U
#define CARRIER_STALL_MS 700U
#define CARRIER_LINK_TIMEOUT_MS 500U
#define CARRIER_MAX_ABS_STEPS 18
#define CARRIER_MAX_ABS_COUNT 12100
#define CARRIER_OBSERVATION_MODE 1
#define CLUTCH_JOG_PWM_PERCENT 45
#define CLUTCH_JOG_DURATION_MS 400U
#define CLUTCH_JOG_ENCODER_TOLERANCE 2
#define MOTOR2_PWM_TO_COUNT_SIGN -1
```

## 2. CE 약어와 enum 숫자

`CE`는 C언어 표준에서 정한 약어가 아니다. 프로젝트 코드에도 풀네임이 명시되어 있지
않다. `CarrierTest`, `CarrierFault`, `CT_*`와 함께 쓰이는 문맥상 `Carrier Error` 또는
`Carrier-test Error`로 해석하는 것이 자연스럽다. `Control Error`라고 확정할 근거는 없다.

현재 enum은 다음과 같다.

```c
enum {
  CE_NONE,               // 0
  CE_COMMAND,            // 1
  CE_LINK,               // 2
  CE_TIMEOUT,            // 3
  CE_STALL,              // 4
  CE_DIRECTION,          // 5
  CE_WHEEL_MOVED,        // 6
  CE_RANGE,              // 7
  CE_DRIFT,              // 8
  CE_CLUTCH_INTERLOCK    // 9
};
```

첫 항목에 숫자를 지정하지 않으면 C 컴파일러가 0부터 시작해서 1씩 증가시킨다. 따라서
`CE_RANGE`는 자동으로 7, `CE_CLUTCH_INTERLOCK`은 자동으로 9가 된다. 중간에 새 항목을
추가하면 뒤의 숫자가 바뀌므로 새 오류는 마지막에 추가하거나 숫자를 명시해야 한다.

## 3. state와 error의 차이

`state`는 제어기의 현재 동작 단계이고 `error`는 fault가 발생한 세부 이유다.

| state | 이름 | 의미 |
|---:|---|---|
| 0 | `CT_UNREFERENCED` | 모드 또는 기준점이 설정되지 않음 |
| 1 | `CT_READY` | 기준 설정 완료, 새 위치 명령 가능 |
| 2 | `CT_MOVING` | 모터2 위치 이동 중 |
| 3 | `CT_DONE` | 목표 도달 후 정지 확인 완료 |
| 4 | `CT_FAULT` | 오류로 정지 |

예를 들어 다음 로그는 서로 다른 두 정보를 나타낸다.

```text
state=4 error=7
```

- `state=4`: 제어기가 FAULT 상태다.
- `error=7`: FAULT 원인은 `CE_RANGE`다.

`error=0`은 오류가 없다는 뜻이므로 state 0, 1, 2, 3과 함께 나타날 수 있다.

## 4. 모든 오류에 공통으로 적용되는 정지 동작

오류가 발생하면 `CarrierFault()`가 실행된다.

```c
static void CarrierFault(CarrierTest *c, uint8_t error)
{
  c->state = CT_FAULT;
  c->error = error;
  c->referenced = 0;
  c->pwm_percent = 0;
  c->clutch_pwm_percent = 0;
  c->clutch_jog_active = 0;
  c->clutch_jog_direction = 0;
}
```

오류 종류와 관계없이 다음 동작이 함께 적용된다.

- `state=4`로 전환
- 세부 오류 번호 저장
- 모터2 기준점 무효화
- 모터2 PWM 0
- 모터3 PWM 0
- 모터3 조그 취소

## 5. 전체 오류 코드 표

| 숫자 | 오류 이름 | 발생 조건 | 먼저 확인할 항목 |
|---:|---|---|---|
| 0 | `CE_NONE` | 오류 없음 또는 모드·기준 설정 정상 완료 | 추가 조치 없음 |
| 1 | `CE_COMMAND` | 알 수 없는 명령, 잘못된 순서, 이동 중 새 명령, 기준 없이 이동, 정지 안정시간 전 명령 | 입력 순서, `state`, 기준 설정 여부 |
| 2 | `CE_LINK` | I2C 오류 신호 또는 마지막 명령 이후 500ms 초과 | SDA/SCL, GND, 주소, wire version, heartbeat |
| 3 | `CE_TIMEOUT` | 모터2 위치 이동이 10000ms 안에 완료되지 않음 | 기계 걸림, 토크, 목표값, 엔코더 |
| 4 | `CE_STALL` | 모터2 이동 중 700ms 동안 2 count 이상 진행하지 못함 | 전원, 드라이버, 구속, PWM, 엔코더 신호 |
| 5 | `CE_DIRECTION` | 목표 반대 방향으로 4 count 초과 이동 또는 p/n의 다음 홈이 요청 방향 반대쪽에 있음 | 방향 핀, 엔코더 방향, PWM/count 부호, 직전 이동 오버슈트 |
| 6 | `CE_WHEEL_MOVED` | 모터2 위치 이동 중 모터1 엔코더가 변함 | 모터1 실제 움직임, 진동, 노이즈, 배선 |
| 7 | `CE_RANGE` | ±18칸 초과, 기준 대비 ±12100 count 초과, 엄격 모드의 목표 통과 | 명령 누적 횟수, 기준점, 실제 count |
| 8 | `CE_DRIFT` | 엄격 모드에서 DONE 후 목표 ±3 count 밖으로 이동 | 관성, 외력, 백래시, 제동 |
| 9 | `CE_CLUTCH_INTERLOCK` | 모터3 조그 중 모터1 또는 모터2가 2 count를 초과해 움직임 | 구동계 끌림, 정지 상태, 엔코더 노이즈 |

## 6. 오류별 상세 설명

### 6.1 CE_NONE = 0

오류가 없다는 뜻이다. `error=0`만 보고 이동 준비가 끝났다고 판단하면 안 되고 state도
함께 확인해야 한다.

```text
state=0 error=0  → 기준 미설정
state=1 error=0  → 이동 준비 완료
state=2 error=0  → 정상 이동 중
state=3 error=0  → 이동 완료
```

### 6.2 CE_COMMAND = 1

현재 제어 상태에서 허용되지 않는 명령이 들어오면 발생한다.

주요 조건은 다음과 같다.

- 모터2 이동 중 새 위치 또는 모드 명령
- 기준점을 설정하지 않고 `→`, `←`, `↓` 입력
- 모터3 조그가 끝나기 전에 새 조그 명령
- `Space` 없이 `1` 또는 `2` 모드 변경
- 엔코더가 정지한 지 300ms가 되기 전에 명령
- `1` 또는 `2` 모드 없이 `↑` 입력
- 허용 목록에 없는 명령 문자

일반적인 복구 순서는 다음과 같다.

```text
Space
→ 300ms 이상 정지
→ 실제 클러치 위치 확인
→ 1 또는 2
→ 실제 홈에서 ↑
```

### 6.3 CE_LINK = 2

STM32가 마지막 정상 명령을 받은 뒤 500ms 이상 새 명령을 받지 못하거나 통신 오류가
전달되면 발생한다.

```c
#define CARRIER_LINK_TIMEOUT_MS 500U
```

ESP32는 약 100ms마다 명령을 전송하므로 정상 상태에서는 500ms 안에 여러 번 갱신된다.
터미널에서 다음 값을 확인한다.

```text
ok=false
writeErr=...
bytesReceived=...
```

확인 순서는 공통 GND, SDA/SCL, STM32 주소, 전원, STM32·ESP32 wire version이다.

### 6.4 CE_TIMEOUT = 3

모터2 위치 이동 시작 후 10초 안에 완료하지 못하면 발생한다.

```c
#define CARRIER_MOVE_TIMEOUT_MS 10000U
```

엔코더가 조금씩 움직여 stall은 피했지만 목표까지 가지 못하는 상황도 timeout이 될 수 있다.
기계 걸림, 낮은 속도, 잘못된 감속비·목표 count와 엔코더 누락을 확인한다.

### 6.5 CE_STALL = 4

모터2 이동 중 엔코더가 700ms 동안 최소 2 count 진행하지 못하면 발생한다.

```c
#define CARRIER_STALL_MS 700U
```

대표적인 원인은 모터 구속, 전원 부족, PWM 부족, 드라이버 문제와 엔코더 단선이다.
`CE_TIMEOUT`은 전체 이동시간 초과이고 `CE_STALL`은 짧은 구간에서 진행 자체가 없는
상태라는 차이가 있다.

### 6.6 CE_DIRECTION = 5

모터2 엔코더가 목표 반대 방향으로 4 count를 초과하면 발생한다. 코드의 비교가 `< -4`이므로
실제로는 반대 방향 5 count부터 fault가 된다. 또한 직전 오버슈트로 다음 20도 홈까지 이미
지나가서 동일한 `p` 또는 `n` 명령이 역방향 PWM을 요구하는 경우, 실제로 역회전하기 전에
이 오류로 정지한다.

현재 실기 확인된 방향 설정은 다음과 같다.

```c
#define MOTOR2_PWM_TO_COUNT_SIGN -1
```

양의 PWM에서 PB3/PB5 엔코더 count가 감소했으므로 count를 증가시키려면 음의 PWM이
필요하다. 모터 배선이나 엔코더 방향을 바꾸면 이 관계를 다시 확인해야 한다.

### 6.7 CE_WHEEL_MOVED = 6

모터2 위치 제어 상태 `CT_MOVING`에서 모터1 엔코더 값이 한 count라도 변하면 발생한다.
모터1이 실제로 움직였는지 먼저 확인하고, 움직이지 않았다면 진동에 따른 접점 변화,
엔코더 노이즈와 잘못된 입력 연결을 확인한다.

모터3 조그 중 다른 엔코더가 움직이는 경우에는 이 코드가 아니라
`CE_CLUTCH_INTERLOCK=9`를 사용한다.

### 6.8 CE_RANGE = 7

허용한 위치 시험 범위를 벗어나면 발생한다.

1. 목표 홈 번호가 -18보다 작거나 +18보다 큼
2. 현재 모터2 count가 기준점에서 ±12100을 벗어남
3. `CARRIER_OBSERVATION_MODE=0`에서 목표를 지나침
4. 계산 결과가 int32 범위를 벗어남

현재 한 칸은 20도이므로 ±18칸은 ±360도다. 클러치 A의 ±18칸은 약 ±12020 count이고,
`CARRIER_MAX_ABS_COUNT=12100`은 여기에 소량의 여유를 둔 전체 제한이다.

현재 `CARRIER_OBSERVATION_MODE=1`에서는 목표 통과만 fault에서 제외한다. ±18칸과
±12100 count 제한은 계속 적용된다.

### 6.9 CE_DRIFT = 8

엄격 모드에서 위치 이동 완료 후 목표 오차가 ±3 count를 벗어나면 발생한다.

현재 설정은 다음과 같다.

```c
#define CARRIER_OBSERVATION_MODE 1
```

따라서 현재 시험 빌드에서는 DONE 후 drift fault 검사가 컴파일에서 제외되어 발생하지 않는다.
관찰 모드를 0으로 바꾸면 다시 활성화된다.

### 6.10 CE_CLUTCH_INTERLOCK = 9

모터3 클러치 조그가 시작될 때 모터1과 모터2 엔코더 기준값을 저장한다. 조그 중 어느
엔코더든 시작점에서 2 count를 초과해 변하면 모든 모터를 정지한다.

```c
#define CLUTCH_JOG_ENCODER_TOLERANCE 2
```

```text
0~2 count 차이 → 허용
3 count 이상 차이 → error=9
```

이 값은 모터3 위치 오차가 아니다. 모터3에는 위치 센서가 없기 때문에 종단 도달이나 체결
완료를 판정하지 못한다. 클러치가 다른 기어를 끌고 가는지, 모터1·2가 완전히 정지했는지,
엔코더 노이즈가 있는지를 감시하는 인터록이다.

## 7. 터미널과 Live Expressions 확인 방법

ESP32 USB 로그에서는 다음 항목을 함께 확인한다.

```text
state=4 clutch=NONE output_deg=0.0 motor3_pwm=0 error=7 motor2_count=...
```

STM32CubeIDE Live Expressions에는 다음 변수를 추가한다.

| 변수 | 확인 내용 |
|---|---|
| `carrier_test.state` | 현재 state 0~4 |
| `carrier_test.error` | CE 오류 번호 0~9 |
| `carrier_test.clutch_mode` | 0=미선택, 1=A, 2=B |
| `carrier_test.target_step` | 현재 목표 홈 번호 |
| `carrier_test.target_count` | 계산된 목표 엔코더 count |
| `carrier_test.zero_count` | `↑`로 저장한 기준 count |
| `carrier_test.pwm_percent` | 모터2 출력 퍼센트 |
| `carrier_test.clutch_pwm_percent` | 모터3 출력 퍼센트 |
| `motor2_encoder_count` | 모터2 실제 count |
| `encoderCount` | 모터1 실제 count |

## 8. 공통 오류 대응 순서

1. 터미널의 `state`, `error`, `motor3_pwm`, `motor2_count`를 기록한다.
2. `Space`를 눌러 정지 명령을 보낸다.
3. 실제 모터가 모두 정지했는지 확인한다.
4. 오류 코드에 따라 통신, 방향, 걸림, 엔코더 또는 범위를 확인한다.
5. 300ms 이상 엔코더가 변하지 않는 상태를 만든다.
6. 실제 클러치 위치에 맞게 `1` 또는 `2`를 선택한다.
7. 실제 홈 위치에서 `↑`를 눌러 기준점을 다시 설정한다.
8. `state=1 error=0`을 확인하고 다음 이동 명령을 한 번만 입력한다.

모터3 방향 시험만 다시 하는 경우에는 `Space`, 300ms 이상 정지, A 또는 B 한 번 입력
순서로 진행한다. 위치 센서가 없으므로 클러치 종단에서 같은 방향을 반복 입력하지 않는다.

## 9. 현재 한계

- 모터3에는 위치·종단 센서가 없어 A/B 체결 성공을 자동 판정하지 못한다.
- `CARRIER_OBSERVATION_MODE=1`은 오버슈트 측정용이며 최종 자동 운전용 판정이 아니다.
- `CE_WHEEL_MOVED`는 한 count 변화에도 반응하므로 실제 하드웨어 노이즈 수준에 대한 추가
  측정이 필요하다.
- enum 숫자는 STM32 상태 패킷의 `error` 필드로 전달되므로 항목 순서를 바꾸면 ESP32,
  PC와 문서의 해석도 함께 변경해야 한다.
