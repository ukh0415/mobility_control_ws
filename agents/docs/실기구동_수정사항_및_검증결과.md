# 실기구동 수정사항 및 검증 결과

## 1. 최종 상태

- 테스트 대상: 다리 1개, STM32 I2C 주소 `0x10` (`leg[0]`)
- 노트북 → ESP32: USB 시리얼 `COM5`, `115200bps`
- ESP32 → STM32: I2C `100kHz`
- 최종적으로 바퀴 모터 실기구동 확인 완료
- ESP32↔STM32 통신은 안정화됨
- Python 콘솔 키 입력 및 정지 명령 동작 확인 완료
- 테스트 종료 시 `k` 정지 명령 전송 및 COM5 해제 확인

현재 한 다리만 연결되어 있으므로 `leg[1]`~`leg[3]`은 조회하지 않도록 설정되어 있다.

## 3. Python 컨트롤러 변경 내용

### 3-1. 키 입력 방식 변경

기존에는 `pynput` 전역 키보드 리스너를 사용했다. 일부 Windows/VS Code/PowerShell 환경에서 키를 눌러도 콜백이 실행되지 않아 명령이 전송되지 않는 문제가 있었다.

현재는 Windows PowerShell 콘솔 입력을 `msvcrt.getwch()`로 직접 읽는다.

```python
import msvcrt

c = msvcrt.getwch()
```

따라서 `pynput`은 더 이상 필요하지 않으며 Python 의존성은 `pyserial`만 있으면 된다.

```powershell
pip install pyserial
```

### 3-2. 현재 조작 방식

이동 명령은 키를 한 번 누르면 계속 전송되고, `k`를 눌러 정지한다.

| 키 | 기능 |
|---|---|
| `i` | 전진 시작 |
| `,` | 후진 시작 |
| `j` | 좌회전 시작 |
| `l` | 우회전 시작 |
| `k` | 정지 |
| `f` | 바퀴/궤도 모드 토글 |
| `1` | 계단 1단계 |
| `2` | 계단 2단계 |
| `ESC` | 정지 명령 전송 후 프로그램 종료 |

이동 명령 반복 전송 주기:

```python
REPEAT_INTERVAL = 0.1
```

### 3-3. 실행 방법

Arduino IDE 시리얼 모니터와 COM5를 사용하는 다른 프로그램을 먼저 닫는다.

```powershell
cd "C:\Users\oiste_pnihbwy\Desktop\대학\공모전\스마트 모빌리티 대학생 창업캠프\제어"
```

```text

[키 입력] k (정지)
```

## 4. ESP32 변경 내용

### 4-1. 한 다리 테스트 설정

현재 연결된 `leg[0]`, 주소 `0x10`만 조회하도록 설정했다.

```cpp
const uint8_t ACTIVE_LEG_COUNT = 1;
```

다음 반복문들이 모두 `ACTIVE_LEG_COUNT`를 사용한다.

- I2C 명령 쓰기 및 상태 읽기
- TCP 상태 전송
- USB 시리얼 상태 출력

이 변경으로 연결되지 않은 `0x11`~`0x13`의 I2C 타임아웃 및 불필요한 실패 로그가 제거됐다.

### 4-2. I2C 타이밍 안정화

기존 설정:

```cpp
POLL_INTERVAL_MS = 50;
delay(10);
```

현재 설정:

```cpp
const unsigned long POLL_INTERVAL_MS = 100;

// Wire.endTransmission() 후 Wire.requestFrom() 전 대기
delay(20);
```

의미:

- 전체 폴링 주기: `50ms`에서 `100ms`로 변경 (`20Hz` → `10Hz`)
- I2C 명령 쓰기 후 상태 읽기 대기: `10ms`에서 `20ms`로 변경

`10ms/20Hz` 시험에서는 60회 중 5회 `bytesReceived=0`이 발생했다.

```text
bytesReceived=3: 55회
bytesReceived=0: 5회
```

`20ms/10Hz`로 변경한 뒤 시험에서는 60회 연속 성공했다.

```text
bytesReceived=3: 60회
bytesReceived=0: 0회
ok=true: 60회
ok=false: 0회
```

### 4-3. 현재 명령 진단 로그 추가

ESP32가 Python에서 받은 현재 명령을 실제로 STM32에 보내는지 확인할 수 있도록 `cmd`를 시리얼 로그에 추가했다.

```cpp
Serial.print("[진단] cmd=");
Serial.print(cmd);
Serial.print(" writeErr=");
```

정상 로그 예시:

```text
[진단] cmd=i writeErr=0 bytesReceived=3
leg[0] addr=0x10 ok=true mode=0 angle=-618.7

[진단] cmd=k writeErr=0 bytesReceived=3
leg[0] addr=0x10 ok=true mode=0 angle=-618.7
```

이 로그로 다음 경로가 정상임을 확인했다.

```text
PowerShell → Python → USB 시리얼 → ESP32 → I2C 주소 0x10
```

### 4-4. 실제 ESP32 업로드 상태

수정 스케치를 ESP32 Dev Module 설정으로 컴파일하고 COM5에 업로드했다.

```text
FQBN: esp32:esp32:esp32
ESP32 core: 3.3.11
대상 포트: COM5
칩: ESP32-D0WD-V3 revision 3.1
```

플래시 쓰기와 해시 검증, RTS 하드 리셋까지 정상 완료했다.

## 5. STM32 실제 프로젝트 확인 결과

팀원에게 받은 `mobility.zip`의 실제 프로젝트를 확인했다.

### 5-1. 바퀴 모터 설정

| 기능 | STM32 핀/타이머 |
|---|---|
| 바퀴 모터 PWM | PA6 / TIM3 CH1 |
| 방향 1 | PA7 |
| 방향 2 | PB0 |
| 엔코더 A상 | PA4 / EXTI4 |
| 엔코더 B상 | PA5 |

TIM3 설정:

```c
htim3.Init.Prescaler = 71;
htim3.Init.Period = 999;
```

PWM 시작 코드도 포함되어 있다.

```c
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
```

`i` 명령은 바퀴 모터에 70% 출력을 설정한다.

```c
case 'i':
  SetMotor(
      &htim3,
      TIM_CHANNEL_1,
      GPIOA, GPIO_PIN_7,
      GPIOB, GPIO_PIN_0,
      (int16_t)(70 * sign));
  break;
```

### 5-2. HANDOFF 문서와 실제 프로젝트 차이

실제 프로젝트에는 HANDOFF의 예시보다 다음 기능이 추가되어 있다.

```c
case '3':  // 선기어 모터 정방향
case '4':  // 선기어 모터 역방향
```

또한 `k` 명령에서 바퀴 모터와 모드 전환 모터뿐 아니라 선기어 모터도 정지한다.

```c
SetMotor(&htim1, TIM_CHANNEL_1, GPIOB, GPIO_PIN_1, GPIOB, GPIO_PIN_10, 0);
```

## 6. 진단 과정 요약

### 초기 증상

- `leg[0] ok=true/false`가 반복됨
- 키보드를 눌러도 조작되지 않음
- `writeErr=0`이지만 `bytesReceived=0`이 간헐적으로 발생

### 확인된 문제와 조치

1. `pynput` 전역 키 이벤트가 실행 환경에서 감지되지 않음
   - `msvcrt.getwch()` 콘솔 직접 입력 방식으로 변경

2. 한 다리 테스트 중에도 연결되지 않은 네 주소 전체를 조회함
   - `ACTIVE_LEG_COUNT=1`로 변경

3. I2C write→read 및 폴링 간격이 현재 하드웨어에서 충분히 안정적이지 않음
   - write→read `20ms`, 폴링 `100ms`로 변경

4. ESP32가 실제로 어떤 명령을 STM32에 전달하는지 로그로 구분하기 어려움
   - `cmd=i`, `cmd=k` 진단 출력 추가

5. 모터와 엔코더가 한때 움직이지 않음
   - 소프트웨어 및 I2C 경로는 정상임을 확인
   - 모터/엔코더 배선 상태 재확인
   - 배선 정비 후 최종 실기구동 확인 완료

## 8. 네 다리 확장 시 변경 사항

STM32 네 개와 주소 `0x10`~`0x13`이 모두 연결되고 검증된 뒤 다음 값을 변경한다.

```cpp
const uint8_t ACTIVE_LEG_COUNT = 4;
```

처음에는 아래 안정화 설정을 유지한다.

```cpp
const unsigned long POLL_INTERVAL_MS = 100;
delay(20);
```

네 다리 모두 장시간 안정적으로 응답한 뒤에만 폴링 주기와 딜레이를 단계적으로 줄인다. 한 번에 모두 줄이지 말고 다음 순서로 각각 시험한다.

1. write→read 딜레이 `20ms` 유지, 폴링 주기만 조정
2. 폴링이 안정적이면 딜레이를 `15ms`로 시험
3. 이후 필요할 때 `10ms` 시험
4. 각 단계에서 `bytesReceived=0` 발생 횟수를 기록

## 9. 안전 및 주의사항

- Arduino IDE 시리얼 모니터와 Python은 COM5를 동시에 열 수 없다.
- 실행 전 바퀴를 지면에서 띄우고 즉시 `k`를 누를 수 있게 준비한다.
- 이동 명령은 키를 놓아도 유지되므로 반드시 `k`로 정지한다.
- 프로그램 종료 시 ESC를 사용한다.
- 비정상 상황에서는 모터 전원을 먼저 차단한다.
- 엔코더 전원은 프로젝트 기준 3.3V를 사용한다.
- ESP32, STM32, L298N, 모터 전원은 공통 GND를 유지한다.
