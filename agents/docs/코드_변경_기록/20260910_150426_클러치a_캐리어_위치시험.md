## 5. 상세 변경 내용과 이유

### 5.1 기준과 이동

- k: 정지. 정지 후 300ms 이상 기다리고 기준 홈에서 z: 기준 저장 및 수동 a 고정 선언.
- p: 기준 +20°, n: 기준 -20°, r: 기준 복귀. 누적 이동 명령이 아니다.
- 동일 명령 재전송은 목표를 다시 설정하지 않는다. 완료 후 같은 동작 재시도는 k 후 명령.
- 이동 중 다른 위치/보정 명령은 fault. 완료(state=3) 또는 정지 후 다음 명령을 보낸다.
- 전체 시험 범위는 기준 대비 ±20°. 현재 계수가 기준에서 ±800 count를 넘으면 fault.
- 환산: 모터2 2404/3 count/rev × 15 × 20/360 = 6010/9 count. ±668로 반올림.
  기준 -6이면 +20 목표 662, -20 목표 -674. 실제 초기 기준에 따라 값은 달라진다.
- carrier angle 0.1° 단위는 (count-zero)×180/601, 정수 절삭. 원시 count는 그대로 전송.

### 5.2 위치 제어와 숫자 근거

10ms 주기에서 목표 오차/12를 PWM%로 사용한다. 최초 구현은 8~20%로 제한했다.
2026-09-10 15:30 KST 실기에서 기준 저장은 성공했으나 p 실행 후 모터에서 PWM 음만 나고
motor2_count=-2가 변하지 않았다. 약 700ms 뒤 state=4가 되어 진행 없음(error=4) 정지가
작동했다. 기동 출력 부족으로 판단하여 후속 수정에서 PWM 범위를 15~40%로 높였다.
40%는 기존 수동 구동 70%보다 낮은 재시험값이며 아직 실기 검증된 최소 기동값이 아니다.
2026-09-10 후속 실기에서 방향 수정 후 count가 0→81까지 증가했으나 기구 부하를
이기지 못하고 정지하여 진행 없음 오류가 발생했다. 사용자 요청에 따라 이동 중 PWM을
계속 70%로 유지하도록 변경했다. 목표 오차가 ±3 count에 들어오면 출력은 즉시 0%가 된다.
기존 오차/12 비례 감속 계산과 15~40% 제한은 제거했다.
이는 저출력 초기 시험값이며 PID/속도 궤적 제어 또는 실기 튜닝 완료값이 아니다.
오차 ±3 count(약 ±0.09°) 이내에서 PWM=0, 모터1/2 카운트가 300ms 변하지 않으면 DONE.
이 허용치는 계수 기준 초기값이며 실제 홈 폭 허용오차로 검증된 값이 아니다.
PWM 0은 현재 드라이버 설정에서 능동 위치 유지/기계 브레이크를 보장하지 않는다.
DONE 후 목표 오차가 3 count를 벗어나면 자동 재구동 없이 drift fault.
목표를 허용오차 이상 지나치면 자동 역회전하지 않고 fault.
현재 카운트 방향 기준 p/n이며 물리적인 시계/반시계 방향은 아직 미확정.
MOTOR2_PWM_TO_COUNT_SIGN=1을 최초 가정하고, 시작점에서 반대쪽으로 4 count 초과 이동하면 fault.
2026-09-10 후속 실기에서 기준 0, p(+668 목표) 명령에 실제 카운트가 0→-10→-12로
감소하여 state=4가 발생했다. 이는 출력은 모터를 움직일 만큼 인가됐지만 출력 방향과
엔코더 증가 방향이 반대임을 보여준다. MOTOR2_PWM_TO_COUNT_SIGN을 -1로 변경하여
p에서는 반대 극성 PWM, n에서는 그 반대 극성 PWM을 사용한다. 배선은 변경하지 않는다.

### 5.3 통신 및 실행 위치

I2C 수신 ISR은 마지막 명령/시간/오류/정지 요청만 저장한다. 모터 출력은 main의 10ms 작업에서 갱신한다.
k 요청은 pending으로 보존하며 빠른 후속 수신이 정지 요청을 덮어쓰지 않게 한다.
main은 IRQ 보호 구간에서 입력을 읽고, 상태/각도 쌍도 보호 구간에서 게시한다.
PC는 선택된 절대 명령 또는 k를 100ms마다 반복하고 재연결 시 k로 초기화한다.
키를 누르고 있어도 같은 목표이며 이동을 누적하지 않는다. 전송 실패 시 연결을 끊는다.
Ctrl+C/ESC는 반복 송신 종료 후 k를 보낸다. 전송 timeout은 0.2초.
ESP32는 USB만 제어 입력으로 받고 TCP는 상태 열람만 허용한다. 기존 TCP 제어 PC는 사용할 수 없다.
I2C 길이/버전/쓰기 오류 시 k 전송. PC 단절 500ms 후 ESP32가 k를 반복한다.

## 6. 영향 범위

PC/ESP32/STM32/공용 프로토콜 모두 영향 있음. 핀, 타이머, .ioc 및 배선 변경 없음.
이 펌웨어에서는 모터1/3 출력을 항상 0으로 강제하고 i/,/j/l/u/o 명령은 허용하지 않는다.
클러치 b, 트랙 연속 주행, 자동 체결, 여러 모듈 제어는 이번 범위 밖이다.
기존 AGENTS.md, launch, IDE 설정과 사용자 문서는 이번 작업에서 수정하지 않았다.

## 7. 프로토콜 호환성

문서 0.3.0-draft, wire version 3. 8바이트 길이/little-endian/count 위치는 유지한다.
byte0은 0 미보정/1 준비/2 이동/3 완료/4 오류, byte1..2는 실제 캐리어 추정각이다.
byte3=3, byte4..7 모터2 raw count. state=0/4이면 angle을 유효한 기준각으로 사용하지 않는다.
TCP 이름 STATUS_A3, USB는 state/carrier_deg/motor2_count. 세 구성요소 동시 갱신 필요.

## 8. 안전 영향과 정지 동작

- 모터3 비사용, 모터1 강제 정지 및 정렬 중 모터1 카운트 변화 시 오류.
- STM32 통신 단절 500ms, 이동 제한 10초, 2 count 이상 진행 없음 700ms에서 오류 정지.
- 잘못된 명령, I2C 오류, 잘못된 상태 전이, 역방향, 초과, 완료 후 이탈도 오류 정지.
- fault 시 보정 무효화. k→원인 확인→실제 홈 재정렬→z로만 재시작.
- 제어는 main에서 수행하므로 로컬 정지는 정상 실행 시 다음 10ms tick에 적용된다.
  CPU 정지/디버거 halt에서 소프트웨어 watchdog은 실행되지 않는다. 구동 중 디버거를 중단하지 않는다.
- 카운트 변화 없음은 실제 고정/체결의 직접 검출이 아니다. 엔코더 단선 상태와 완전 정지는
  정지 중 구분할 수 없으며 구동 시 무응답 timeout으로 제한한다.
- 클러치 a는 사용자가 기계적으로 고정/확인하는 시험 전제이며 센서 기반 체결 확인 구현이 아니다.

## 12. 남은 위험과 후속 작업

1. STM32/ESP32를 새로 빌드·업로드. 모터 구동 전원은 끄고 로직은 유지한다.
2. 클러치 a 기계 고정, 기준 홈 맞춤. PC 실행 후 k 상태로 충분히 대기, z 입력.
3. state=1 및 carrier_deg=0 확인. 필요하면 Live Expressions에서
   carrier_test.zero_count, target_count, state, error, pwm_percent 및 motor2_encoder_count 관찰.
4. 안전한 무부하 단일 모듈에서 구동 전원을 켜고 p 한 번. state=3으로 완료되면 실제 홈 오차 확인.
5. 완료 후 r 복귀 확인, 이후 n 시험. k는 언제든 정지. fault면 원인 확인 전 재시도하지 않는다.
6. error 값: 0 없음, 1 명령/상태, 2 통신, 3 총시간, 4 진행 없음, 5 반대 방향,
   6 모터1 움직임, 7 범위/초과, 8 완료 후 이탈. 현재 오류 상세는 Live Expressions에서 확인한다.
7. 고정 70% 펌웨어에서 다시 시험한다. p 시 count가 증가해야 한다. 목표 접근 감속이 없으므로
   k에 즉시 접근할 수 있게 준비하고, 목표 초과·충격·진동을 관찰한다. 반대로 감소하거나
   움직이지 않으면 즉시 k 후 기동전류/전압/마찰과 링기어 고정 상태를 확인한다.
