## 2. 변경 목적

ESP32가 STM32를 100ms마다 polling할 때마다 진단과 상태를 USB 시리얼에 출력해 PC 터미널이
빠르게 밀리는 문제를 해결한다. 제어·상태 읽기 속도는 유지하면서 사람이 보는 로그만 줄인다.

## 3. 변경 전 동작

`loop()`의 100ms polling 블록이 실행될 때마다 `pollAllLegs()`에서 `[진단]` 한 줄,
`printStatusToSerial()`에서 상태 한 줄을 출력했다. 정지 상태에서도 초당 약 20줄이 계속
출력됐다. `POLL_INTERVAL_MS`를 늘리면 로그는 줄지만 명령 전달, 상태 변화 감지와 통신
failsafe 관찰도 함께 느려지는 문제가 있었다.

## 5. 상세 변경 내용과 이유

### 5.1 상태 읽기 주기 유지

`POLL_INTERVAL_MS=100`을 변경하지 않았다. 따라서 ESP32는 100ms마다 명령을 STM32에 쓰고,
9바이트 상태를 읽으며 TCP 상태도 갱신한다. 모터 제어는 STM32의 10ms 작업에서 계속 수행된다.

### 5.2 터미널 출력 조건

기존 `printStatusToSerial()`을 `printStatusToSerialIfNeeded()`로 바꿨다. 다음 조건 중 하나일
때만 USB 시리얼 상태를 출력한다.

1. 프로그램 시작 후 첫 상태
2. I2C 통신 `ok`가 성공에서 실패 또는 실패에서 성공으로 변경
3. STM32 state가 변경
4. 선택 clutch mode가 변경
5. state=2인 동안 마지막 진행 로그에서 1000ms 경과

따라서 키 입력으로 READY→MOVING, MOVING→DONE 또는 FAULT 같은 상태 전이가 생기면 다음
100ms polling에서 즉시 한 번 표시된다. 이동이 길면 현재 output/count를 1초마다 확인할 수 있다.

### 5.3 정상 진단 반복 제거와 오류 정보 보존

`pollAllLegs()`에서 매번 출력하던 `[진단] cmd/writeErr/bytesReceived` 블록을 제거했다.
대신 `LegStatus`에 마지막 `write_error`와 `bytes_received`를 저장한다. 통신이 실패해 `ok=false`로
변하는 순간 출력되는 상태 줄에 두 값을 함께 표시하므로 오류 분석 정보는 유지된다.

### 5.4 출력량 조절 방법

```cpp
const unsigned long STATUS_PROGRESS_LOG_MS = 1000;
```

- `1000`: 현재 설정. 이동 중 약 1초마다 진행 상태 출력
- `2000`: 이동 중 약 2초마다 출력
- `0`: 이동 중 정기 출력 없음. 시작·상태·모드·통신 변화 때만 출력

이 값을 바꿔도 I2C sampling 주기에는 영향이 없다. 실제 읽기 주기는 별도 상수인
`POLL_INTERVAL_MS=100`이 담당한다.

## 6. 영향 범위

| 영역 | 영향 | 설명 |
|---|---|---|
| Python/PC | 없음 | ESP32가 보낸 줄을 그대로 출력하는 구조 유지 |
| ESP32 | 있음 | USB 출력 조건과 오류 진단 저장 변경 |
| STM32 | 없음 | 제어 주기와 상태 생성 변경 없음 |
| 공용 프로토콜 | 없음 | 9바이트 version 5 패킷과 명령은 그대로 |
| 하드웨어·배선 | 없음 | 핀과 배선 변경 없음 |

## 7. 프로토콜 호환성

wire version 5와 `STATUS_AB5` 데이터 형식은 변경하지 않았다. USB 사람이 읽는 로그의 빈도만
줄였다. TCP 상태 전송은 기존처럼 polling마다 수행한다.

## 8. 안전 영향과 정지 동작

명령 전달, I2C polling, ESP32 500ms failsafe와 STM32 로컬 안전 조건은 변경하지 않았다.
통신 실패와 FAULT는 변화 이벤트로 즉시 출력된다. 로그가 적어져도 모터 정지 동작은 늦어지지 않는다.

## 10. 확인하지 못한 항목

실제 보드에서 첫 상태, 1초 이동 진행, DONE, FAULT 및 I2C 단절·복구가 각각 한 번씩
표시되는지는 확인하지 못했다.

## 11. 되돌리기 방법

`loop()`에서 기존처럼 매 polling마다 상태 함수를 호출하고 `pollAllLegs()`의 진단 출력을
복원하면 된다. 상태 읽기와 패킷 코드는 되돌릴 필요가 없다.

## 12. 남은 위험과 후속 작업

ESP32만 다시 빌드·업로드한 후 정지 상태에서 로그가 반복되지 않는지 확인한다. A/B 이동을
한 번 실행해 MOVING 시작, 1초 진행 로그, DONE이 표시되는지 확인한다. 더 적은 출력이 필요하면
`STATUS_PROGRESS_LOG_MS=0`으로 변경한다.
