## 2. 변경 목적

클러치 a에서 링기어를 수동 고정한 캐리어 위치 시험 중 `p` 또는 `n`을 누를 때마다
기준 홈을 중심으로 목표가 각각 +20도 또는 -20도씩 누적되게 한다. 시리얼과 I2C의
주기적 재전송은 한 번의 키 입력을 여러 위치 명령으로 잘못 해석하지 않아야 한다.

## 3. 변경 전 동작

`p`는 항상 기준점의 +20도, `n`은 항상 기준점의 -20도를 목표로 했다. 따라서 +20도
이동 완료 후 `p`를 다시 눌러도 +40도로 진행할 수 없었다. PC는 선택한 위치 명령 문자를
계속 반복하여 전송했으므로 STM32에서 단순히 수신 횟수마다 목표를 증가시킬 수도 없었다.

## 5. 상세 변경 내용과 이유

### 5.1 누적 목표

- 기준 홈에서 `z`를 누르면 목표 홈 번호 `target_step=0`으로 저장한다.
- READY(1) 또는 DONE(3)에서 `p`를 한 번 누르면 홈 번호를 +1, `n`은 -1 한다.
- `r`은 홈 번호를 0으로 만들고 저장된 기준점으로 복귀한다.
- 목표 count는 `zero_count + round(target_step × 6010/9)`로 매번 기준점에서 직접 계산한다.
  668 count를 계속 더할 때 생기는 정수 반올림 누적 오차를 피하기 위한 방식이다.
- 예를 들어 기준 count가 -6이면 홈 번호 1 목표는 662, 홈 번호 2 목표는 1330이다.
- 시험 범위는 기준점에서 ±18칸(±360도), raw 상대 count는 ±12100으로 제한한다.

### 5.2 한 키 입력과 통신 반복의 구분

PC는 `p/n/r/z` 키를 누르면 해당 문자를 약 300ms 동안 100ms 간격으로 전송한 뒤 `h`로
바꾼다. ESP32의 100ms polling에서 키 문자가 누락되지 않게 하면서, 같은 문자 반복을
한 번의 명령으로 유지한다. STM32는 문자가 `h`에서 새 `p/n/r`로 바뀔 때만 다음 목표를
생성한다. `h`는 현재 목표와 이동 상태를 변경하지 않는 통신 heartbeat이다.

PC는 마지막으로 수신한 `state`가 READY(1) 또는 DONE(3)일 때만 `p/n/r`을 허용한다.
이동 중 새 목표를 넣으면 STM32에서도 명령 오류로 정지한다. 연결이 새로 생기거나
프로그램이 종료되면 명령 상태는 `k`로 돌아간다.

### 5.3 정지와 기준 유효성

이동 중 `k`로 취소하면 중간 위치가 홈인지 알 수 없으므로 저장 기준을 무효화한다.
사용자가 기구를 실제 기준 홈에 다시 맞춘 뒤, 정지 상태에서 `z`를 다시 입력해야 한다.
고정 70% PWM, 목표 허용오차, stall/timeout 및 다른 안전 조건은 이전 시험 설정을 유지한다.

## 6. 영향 범위

| 영역 | 영향 | 설명 |

## 7. 프로토콜 호환성

공용 문서 버전은 `0.4.0-draft`, 상태 wire version은 4이다. 8바이트 길이,
little-endian, 상태·각도·raw count 필드 위치는 유지한다. ESP32는 byte3이 4가 아니면
응답을 거부하므로 PC/ESP32/STM32를 함께 갱신해야 한다. TCP 상태 접두사는 `STATUS_A4`이다.

## 8. 안전 영향과 정지 동작

- 이동 중 새 위치 명령, 범위 초과, 역방향, stall, 총 이동 timeout, 모터1 움직임,
  통신 단절 또는 I2C 오류는 기존과 같이 fault 및 PWM 0으로 처리한다.
- 누적 범위는 ±18칸으로 제한한다. 제한을 넘는 입력은 자동 순환하지 않는다.
- 이동 중 `k`는 즉시 정지시키고 기준을 무효화해 중간 위치에서의 후속 자동 이동을 막는다.
- 클러치 a 체결은 센서로 확인하지 않는다. 사용자가 링기어를 수동 고정한 시험에서만 사용한다.
- PWM은 계속 70%이며 목표 근처 감속 제어는 아직 없다. 실제 기구에서는 `k`에 즉시 접근할 수
  있게 하고 단일 모듈·무부하에서 한 칸씩 시험한다.

단위 테스트는 같은 `p`의 반복 수신이 한 번만 반영되는지, `h`가 진행 목표를 유지하는지,
DONE 후 새 `p`가 +40도 목표를 만드는지, `n`이 한 칸 감소시키는지, 이동 중 `k`가 기준을
무효화하는지, ±18칸 초과가 fault인지 확인한다.

## 10. 확인하지 못한 항목

첫 +20도 이동에서 통신과 누적 목표 시작은 확인했다. 그러나 고정 70% 출력으로 목표
1416을 지나 1434에서 fault가 발생했고, 출력 차단 후에도 관성으로 1511까지 이동했다.
Live Expressions의 `carrier_test.error`를 함께 기록하지 않아 세부 오류 코드는 미확정이나,
로그와 제어 조건상 목표 초과 `CE_RANGE(7)`가 가장 유력하다. 실제 기구에서 감속·제동 거리,
연속 홈 이동, 정지 오차, 각 홈의 기계 공차, ±360도까지의 케이블/기구 가동 범위는 미확인이다.
컴파일 확인과 실기 검증 완료는 구분해야 한다.

## 11. 되돌리기 방법

이 기록의 수정 파일에서 version 4 누적 홈 번호와 `h` 처리를 제거하고 PC/ESP32/STM32를
동시에 version 3 절대 ±20도 방식으로 복구한다. 기존 사용자 변경을 포함한 전체 작업 트리
reset은 사용하지 않는다.

## 12. 남은 위험과 후속 작업

1. 변경된 STM32와 ESP32를 각각 빌드·업로드하고 PC 프로그램을 다시 실행한다.
2. 링기어를 수동 고정하고 캐리어 기준 홈을 맞춘 뒤 `k`, 300ms 이상 대기, `z` 순으로 입력한다.
3. 다음 시험 전에 70% 고정 출력 대신 목표 전 감속 또는 조기 출력 차단 방식을 정하고,
   `carrier_test.error`, `target_count`, `motor2_encoder_count`, `pwm_percent`를 동시에 관찰한다.
4. `state=1`, `carrier_deg=0.0`을 확인한 다음 `p`를 한 번 입력하고 DONE(3)을 기다린다.
5. 다음 `p`는 기준 +40도, `n`은 다시 +20도, `r`은 기준 0도를 목표로 하는지 확인한다.
6. 각 이동 후 실제 홈 정렬과 raw count를 기록한다. fault면 `carrier_test.error`를 확인하고
   원인을 제거한 뒤 실제 홈 재정렬 및 `z`부터 다시 시작한다.
