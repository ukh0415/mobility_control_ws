## 2. 변경 목적

- 고정 70% 모터2 위치제어에서 목표 통과와 최종 오버슈트를 시간 그래프로 확인한다.
- 키보드 명령을 한글 버튼으로 제공한다.
- 실제 소스 튜닝값을 UI에 표시하고 범위 검사 후 헤더에 저장할 수 있게 한다.
- 완전조립 전 단계별 시험과 손 튜닝 판단 기준을 문서화한다.

## 3. 변경 전 동작

- PC는 저빈도 사람용 ESP32 로그만 받아 시간에 따른 count 궤적을 표시할 수 없었다.
- STM32 상태 패킷에는 실제 count만 있었고 목표 count와 모터2 PWM이 없었다.
- 제어는 키보드 입력만 지원했고 소스 상수는 IDE에서 직접 찾아야 했다.

## 5. 상세 변경 내용과 이유

### 5.1 텔레메트리

- STM32 응답에 목표 count, 실제 모터2 PWM과 목표 홈 번호를 추가했다.
- ESP32는 UI 요청 `v`를 로컬에서 소비하고 100ms마다 `TELEM_M37`을 출력한다.
- `V`로 스트리밍을 끄며 이 문자는 STM32 명령으로 전달하지 않는다.
- 평소 사람용 로그는 기존 2초 주기를 유지한다.

### 5.2 UI

- localhost 브라우저 UI와 HTML Canvas로 실제·목표 count와 PWM을 표시하여 외부 그래프
  패키지나 Tcl/Tk 런타임이 필요 없다.
- 노트북 한 화면에서 상태·버튼·그래프·튜닝값을 함께 볼 수 있도록 글자, 여백, 상태 카드,
  튜닝 행과 로그 높이를 줄였다. 화면 폭이 좁으면 한 열로 자동 전환한다.
- `state=0`, 계산 모드 미선택처럼 정상적인 초기 상태에서도 일부 버튼이 잠기는 이유를 바로
  알 수 있도록 `계산모드 선택 → 홈 저장 → ±20° 이동`의 다음 동작 안내를 표시한다.
- 활성화된 버튼에는 선명한 내부 테두리를 추가하여 비활성 버튼과 구분했다.
- 초기 UI의 JavaScript 함수 이름 `command()`가 최신 HTML 버튼의 `command` 속성과 충돌해
  클릭 함수가 호출되지 않을 수 있던 문제를 `sendMotorCommand()`로 이름을 바꿔 해결했다.
- 새 파일 적용 여부를 확인할 수 있도록 상단에 `UI rev.2`, 버튼 API 접수 여부를 확인할 수
  있도록 `최근 버튼: 문자 (서버 접수 완료)` 표시를 추가했다.
- 통신 로그 내용이 추가될 때 로그 영역의 스크롤을 자동으로 맨 아래로 이동하여 항상 최신
  메시지가 보이게 했다.
- 기존 모든 시험 명령을 한글 버튼으로 제공한다.
- 상태에 맞지 않는 버튼은 비활성화하고 STM32 로컬 인터록을 최종 안전 계층으로 유지한다.
- 수집 데이터를 CSV로 저장한다.
- `carrier_test.h` 상수를 읽고 저장하되 Build/Flash 필요 문구를 항상 표시한다.

### 5.3 현재 제어 범위

- 제어 알고리즘은 계속 고정 70% ON/OFF 방식이다.
- 이번 변경은 측정 도구를 추가하며 단계식 감속이나 PID는 아직 적용하지 않는다.
- 모터3 현재 시험값 45%, 400ms를 표시·테스트와 맞췄다.

## 7. 프로토콜 호환성

- 응답 길이가 11바이트에서 18바이트로 바뀌므로 STM32와 ESP32를 함께 갱신해야 한다.
- byte 0~10 의미는 유지하고 byte 11~17에 새 필드를 추가했다.
- wire version은 7, TCP/사람 로그 접두사는 `STATUS_M37`, UI 텔레메트리는 `TELEM_M37`이다.
- 다중 바이트 값은 little-endian을 유지한다.

## 8. 안전 영향과 정지 동작

- UI는 연결 직후 `k`를 전송하고 종료 시 `k`와 텔레메트리 종료를 전송한다.
- 상태를 받기 전 이동 버튼을 비활성화한다.
- 계산 모드와 클러치 조그 버튼은 정지 후 350ms 대기하고 명령을 보낸다.
- STM32의 link timeout, stall, 이동 timeout, 방향, 범위, 모터1 움직임과 클러치 인터록은 유지한다.
- 텔레메트리 활성화는 명령 전달과 모터 제어 주기를 바꾸지 않는다.

## 11. 되돌리기 방법

- PC UI 파일을 제거하고 version 6의 11바이트 상태 정의로 STM32·ESP32·프로토콜을 함께 되돌린다.
- 패킷 한쪽만 되돌리면 I2C 응답 길이가 달라져 통신 실패 정지가 발생한다.

## 12. 남은 위험과 후속 작업

- 100ms 표본은 10ms 제어의 모든 순간을 포착하지 않는다.
- 헤더 저장 후 보드를 다시 Flash하기 전에는 소스값과 실행값이 다르다.
- 위치 센서 없는 모터3의 체결 완료는 여전히 사용자가 확인한다.
- 기준 데이터를 수집한 뒤 단계식 감속, P 또는 PD 제어를 별도 변경으로 구현한다.
