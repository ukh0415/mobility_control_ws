## 2. 변경 목적

모터3을 사용하지 않고 클러치를 손으로 A/B에 고정해, 모터2의 15:1 캐리어 이동과 12:1
링기어 이동을 한 시험 프로그램에서 선택하고 20도 단위 왕복 오차를 측정한다. 기존에
떨어져 있던 p/n/k/z 사용자 키는 화살표·Space·숫자 키 중심으로 바꾼다.

## 3. 변경 전 동작

클러치 A의 캐리어 15:1만 지원했다. p/n은 20도씩 누적됐지만 클러치 B의 12:1 환산과
A/B 선택 상태가 없었다. 상태 패킷에는 선택 클러치 모드가 없었고 각도 이름도 캐리어로
고정돼 있었다.

## 5. 상세 변경 내용과 이유

- `1→a`, `2→b`, `←→n`, `→→p`, `↑→z`, `↓→r`, `Space→k`로 변환한다.
- 모드 선택 a/b는 직전 명령이 k이고 정지한 경우에만 허용하며 이전 기준을 무효화한다.
- A는 `round(step×6010/9)`, B는 `round(-step×4808/9)`를 기준 count에 더한다.
- B의 음수 부호는 캐리어 고정 시 링기어와 모터 입력의 회전 방향이 반대인 관계를 반영한다.
- A 출력각은 `delta×180/601` 0.1도, B 출력각은 `-delta×225/601` 0.1도로 계산한다.
- PWM 70% 및 오버슈트 관찰 모드의 정지 방식은 유지한다.

## 7. 프로토콜 호환성

문서 버전은 0.5.0-draft, wire version은 5다. 상태 응답은 8바이트에서 9바이트로 변경했다.
byte4에 clutch mode를 추가하고 raw motor2 count는 byte5..8로 이동했다. TCP 접두사는
`STATUS_AB5`다. 구형 ESP32는 새 STM32 응답을 읽지 못하므로 둘을 함께 업로드해야 한다.

## 8. 안전 영향과 정지 동작

- 모터1/3은 계속 PWM 0으로 강제한다.
- 모드 변경에는 먼저 k가 필요하고 선택 즉시 기준을 무효화한다.
- 클러치 상태는 센서로 검출하지 않으므로 실제 수동 고정과 선택 모드 일치는 사용자가 확인한다.
- 통신 단절, I2C 오류, stall, 10초 timeout, 역방향, 모터1 움직임, 명령/범위 오류 정지는 유지한다.
- 오버슈트 관찰 모드에서는 목표 통과 후 PWM 0, 관성 정지 후 DONE을 유지한다.

## 11. 되돌리기 방법

PC/ESP32/STM32를 함께 version 4로 되돌리고 B 환산, a/b 명령과 상태 byte4를 제거한다.
기존 사용자 파일을 포함한 작업 트리 전체 reset은 사용하지 않는다.

## 12. 남은 위험과 후속 작업

1. STM32와 ESP32를 모두 새로 빌드·업로드하고 PC 프로그램을 재시작한다.
2. A에서 키 배치와 기존 15:1 결과가 유지되는지 먼저 확인한다.
3. Space로 정지한 뒤 B를 손으로 고정하고 `2→↑`로 기준을 새로 잡는다.
4. B의 오른쪽 화살표 방향과 약 534 count 이동을 확인한다. 반대면 B 환산 부호를 수정한다.
5. 각 p/n/r 왕복의 목표 count, 최종 count, output_deg, 실제 홈 오차를 표로 기록한다.
