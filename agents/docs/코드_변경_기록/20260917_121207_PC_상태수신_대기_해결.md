# 20260917_121207 PC 상태수신 대기 해결

## 1. 기록 정보

- 작업 일시: 2026-09-17 12:12 KST
- 대상: 모터2 위치·모터3 클러치 조그 단일 모듈 시험
- 증상 로그: COM7 연결과 Space 전송 후 A/B 입력 시 `state=None`으로 거부

## 2. 변경 목적

ESP32가 계속 켜진 상태에서 PC 프로그램만 다시 연결해도 PC가 현재 STM32 상태를 받아
안전 조건을 판정할 수 있게 한다. 사용자가 40%에서 45%로 올린 모터3 PWM 설정도 PC 표시,
시험과 문서에 일치시킨다.

## 3. 변경 전 동작

- ESP32는 STM32 상태를 100ms마다 읽었지만 USB에는 상태가 바뀔 때만 출력했다.
- ESP32의 안정 상태가 PC 연결 전에 이미 한 번 출력됐다면 새 PC 프로세스는 상태 줄을 받지
  못해 `last_state=None`과 `last_motor3_pwm=None`을 유지할 수 있었다.
- PC는 이 경우를 모터2 정지 미확인과 같은 문구로 표시했다.
- STM32의 실제 모터3 PWM은 사용자가 45%로 수정했지만 PC 문구, 시험과 문서는 40%였다.

## 5. 상세 변경 내용과 이유

- 상태 변화가 없더라도 ESP32가 2000ms마다 USB 상태 한 줄을 출력한다.
- 상태 변화는 기존처럼 즉시 출력하고, 모터2 MOVING 진행 로그는 기존처럼 1000ms마다 출력한다.
- I2C polling 100ms와 모터 제어 주기는 바꾸지 않았다.
- PC가 아직 어떤 상태도 받지 못했다면 A/B를 계속 거부하되 최대 2초 기다리라는 정확한
  원인을 표시한다. 안전 확인 없이 모터3을 허용하지 않는다.
- 모터3 조그 크기는 45%, STM32 자체 자동 정지 시간은 250ms로 유지한다.

## 6. 영향 범위

- ESP32 USB 로그가 안정 상태에서 2초에 한 줄 출력된다.
- PC 재연결 후 최대 2초 이내에 `last_state`와 `last_motor3_pwm`이 채워진다.
- 모터3 구동 크기는 ±45%로 표시되고 시험된다.
- 모터2 위치 계산, 클러치 감속비, I2C 패킷 길이와 필드 배치는 변하지 않는다.

## 7. 프로토콜 호환성

- wire version은 6으로 유지한다.
- STM32 응답 11바이트와 `STATUS_M36` 형식은 변경하지 않는다.
- USB 로그 출력 정책과 현재 PWM 설정 설명만 갱신했다.

## 8. 안전 영향

- 상태를 받기 전 모터3 명령을 허용하지 않는 기존 fail-closed 동작을 유지한다.
- 2초 재출력은 상태 관찰만 추가하며 모터 명령이나 제어 주기에 영향을 주지 않는다.
- 모터3 PWM은 45%로 증가했지만 한 번의 조그는 STM32에서 최대 250ms 후 자동 정지한다.
- 모터1·2 정지 인터록과 조그 중 엔코더 이동 감시는 유지한다.
