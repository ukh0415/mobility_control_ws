# 캐리어 목표 초과로 인한 state=4

## 발생 시각과 환경

- 발생 시각: 2026-09-10 실기 시험, 2026-09-11 분석 및 임시 시험 모드 적용
- 대상: STM32F103C8T6 단일 모듈, 클러치 a 수동 고정, 모터2 고정 PWM 70%
- 제어: PC `z` 기준 설정 후 `p`로 캐리어 +20도 이동

## 사용한 코드 버전 또는 Git 커밋

- 분석/수정 기준 커밋: `34f4657`
- 작업 브랜치: `feature/test`
- 상태 wire version: 4

## 증상

기준 count 748에서 `z`를 누른 뒤 `p`를 눌렀다. 캐리어는 눈으로 보기에 약 20도
회전했지만 터미널 상태가 DONE(3)이 아니라 FAULT(4)가 됐다. 이후 PC가 `p/n/r` 명령을
거부해 왕복 오차 시험을 계속할 수 없었다.

## 재현 절차

1. 링기어를 수동 고정한다.
2. 캐리어 기준 홈에서 `k`, 300ms 이상 대기, `z`를 입력한다.
3. `state=1`, count 748을 확인한다.
4. `p`를 한 번 입력한다.
5. count가 목표를 통과할 때 `state=4`가 되는지 확인한다.

## 기대 동작

이번 오차 측정 시험에서는 목표를 통과하는 순간 PWM을 0으로 만들고, 관성 이동까지
멈춘 실제 count와 각도를 유지한 채 DONE(3)이 되어야 한다. 그러면 다음 `p/n/r`을 입력해
누적 이동 및 원점 복귀 오차를 계속 측정할 수 있다.

## 조사 내용과 측정값

20도당 목표 이동량은 약 668 count이다.

```text
기준 count = 748
목표 count = 748 + 668 = 1416
```

관찰 로그는 다음 순서였다.

```text
count 1339, carrier 17.6°, state=2
count 1434, state=4
count 1494
count 1511
count 1507에서 정지
```

목표 1416을 처음 관찰한 1434에서 이미 18 count 넘었다. PWM 차단 뒤에도 관성으로
1511까지 진행했다. 최종 1507을 기준으로 계산하면 상대 count는 759이고 캐리어 추정각은
약 22.7도이다.

## 원인

원인은 고정 70% PWM과 엄격한 목표 초과 판정의 조합이다. 기존 제어는 목표까지 70%를
유지하다가 목표 오차 ±3 count에 들어오면 PWM을 0으로 만든다. 한 제어 주기 사이에 목표를
통과하거나, PWM을 끈 뒤 관성으로 허용 범위를 벗어나면 오류로 처리했다.

### CE_RANGE와 숫자 7의 의미

`CE_RANGE`는 변수에 7을 직접 대입하는 설정값이 아니다. C의 `enum`은 이름에 숫자를
순서대로 붙여 주는 문법이다.

```c
enum {
  CE_NONE,          // 0
  CE_COMMAND,       // 1
  CE_LINK,          // 2
  CE_TIMEOUT,       // 3
  CE_STALL,         // 4
  CE_DIRECTION,     // 5
  CE_WHEEL_MOVED,   // 6
  CE_RANGE,         // 7
  CE_DRIFT          // 8
};
```

첫 이름 `CE_NONE`이 0이고 다음 이름마다 1씩 증가하므로 `CE_RANGE`가 자동으로 7이 된다.
`CarrierFault(c, CE_RANGE)`를 실행하면 `CarrierFault` 함수가 `c->error`에 7을 저장하고,
상태를 `CT_FAULT`, 즉 숫자 4로 바꾸며 PWM을 0으로 만든다.

```c
static void CarrierFault(CarrierTest *c, uint8_t error)
{
  c->state = CT_FAULT;
  c->error = error;
  c->referenced = 0;
  c->pwm_percent = 0;
}
```

따라서 터미널의 `state=4`와 Live Expressions의 `carrier_test.error=7`은 서로 다른 값이다.

- `state=4`: 현재 제어 상태가 FAULT라는 뜻
- `error=7`: FAULT가 된 세부 이유가 CE_RANGE라는 뜻

기존 코드에서 CE_RANGE는 세 상황에 사용됐다.

1. 목표 홈 번호가 ±18칸을 넘거나 int32 범위에서 목표 count를 만들 수 없는 경우
2. 현재 위치가 기준점에서 ±12100 count를 벗어난 경우
3. 이동 중 목표 count를 지나친 경우

이번 변경은 3번의 목표 초과만 fault에서 제외한다. 1번과 2번의 전체 시험 범위 제한은
그대로 유지한다. `CE_RANGE`라는 이름과 숫자 7도 삭제하지 않는다.

## 해결 또는 임시 조치

`CARRIER_OBSERVATION_MODE`를 1로 추가했다.

```c
#define CARRIER_OBSERVATION_MODE 1
```

이 모드에서는 목표 허용오차에 들어오거나 목표를 통과하면 `target_reached=1`로 표시하고
PWM을 즉시 0으로 유지한다. count가 300ms 동안 변하지 않으면 최종 오차가 ±3 count보다
커도 DONE(3)으로 전환한다. DONE 이후 위치가 밀려도 `CE_DRIFT` fault를 발생시키지 않는다.

PWM 크기는 70%로 유지했다. 목표 통과 이후에는 방향을 반대로 바꿔 자동 보정하지 않으며,
PWM 0 상태로 관성 정지만 관찰한다.

계속 유지되는 정지 조건은 다음과 같다.

- 통신 단절 또는 I2C 오류
- 700ms 동안 엔코더 진행 없음
- 전체 이동 시간 10초 초과
- 시작 직후 목표 반대 방향 이동
- 모터1 엔코더 움직임
- 잘못된 명령 또는 상태 전이
- 목표 홈 번호 ±18칸과 상대 count ±12100 범위 초과

## 검증 결과

- MSVC `/W4`로 제어기 단위 테스트 컴파일 및 실행 성공
- 목표 662를 지나 count 670, 710으로 관성 이동하는 상황에서 PWM 0 유지 확인
- count 710에서 300ms 정지 후 DONE(3) 확인
- DONE 후 추가 위치 변화가 있어도 fault로 바뀌지 않음을 확인
- 이후 `n` 입력이 목표 홈 번호를 0으로 낮추고 반대 방향 70% 이동을 시작함을 확인
- Python 문법 검사 및 기존 PC 테스트 3개 통과
- 실제 STM32/ESP32 업로드와 기구 왕복 시험은 미수행

## 남은 위험과 후속 작업

이 모드는 최종 위치가 홈 허용 범위 안인지 확인하지 않고 DONE을 내므로 자동 클러치 체결에
사용하면 안 된다. 사용자는 각 명령 후 터미널의 `carrier_deg`와 `motor2_count`를 기록하고,
실제 홈 중심과의 차이도 함께 관찰해야 한다. 충분한 왕복 데이터를 모은 뒤 목표 전 출력 차단,
감속 PWM, 능동 제동 또는 위치 센서를 포함한 최종 완료 판정으로 교체한다.
