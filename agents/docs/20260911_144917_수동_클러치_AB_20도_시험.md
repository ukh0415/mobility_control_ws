# 수동 클러치 A/B 20도 위치 시험

## 목적

모터3으로 클러치를 자동 전환하기 전에 사용자가 클러치를 손으로 고정하고, 모터2 하나로
클러치 A와 B의 20도 홈 이동량 및 왕복 오차를 같은 시험 프로그램에서 측정한다. 두 상태를
동시에 구동하는 것이 아니라, 정지 상태에서 A/B 제어식을 선택해 순서대로 시험한다.

## 기계 상태와 환산

| 시험 모드 | 손으로 고정하는 부품 | 움직이는 출력 | 감속비 | 출력 +20도당 모터2 엔코더 목표 변화 |
|---|---|---|---:|---:|
| A | 링기어 | 캐리어 | 15:1 | `+6010/9 ≈ +667.78 count` |
| B | 캐리어 | 링기어 | 12:1 | `-4808/9 ≈ -534.22 count` |

엔코더 실측 평균은 모터축 1회전당 `2404/3 count`이다.

클러치 A 계산:

```text
모터 회전각 = 캐리어 20° × 15 = 300°
count = (2404/3) × (300/360)
      = 6010/9
      ≈ 667.78 count
```

클러치 B 계산:

```text
모터 회전각 크기 = 링기어 20° × 12 = 240°
count 크기 = (2404/3) × (240/360)
           = 4808/9
           ≈ 534.22 count
```

캐리어를 고정하면 링기어는 모터 입력과 반대 방향으로 움직이는 유성기어 관계이므로,
동일한 출력축 +20도 정의에 대해 B의 엔코더 목표 부호를 A와 반대로 설정했다. 이는
운동학에 따른 초기 부호이며 첫 B 실기에서 오른쪽 화살표의 실제 방향을 확인한다.

## 키 배치

기존 문자는 통신 내부 의미를 빠르게 구분하려고 사용했다.

- `p`: positive, 목표 +20도
- `n`: negative, 목표 -20도
- `k`: kill/stop
- `z`: zero 설정

이 문자는 구현에는 편하지만 키보드에서 떨어져 있다. 사용자 입력은 다음과 같이 바꾸고,
PC가 내부적으로 기존 한 글자 명령으로 번역한다.

| 키 | 사용자 동작 | 내부 문자 |
|---|---|---|
| `1` | 클러치 A 제어식 선택 | `a` |
| `2` | 클러치 B 제어식 선택 | `b` |
| `←` | 목표 -20도 한 칸 | `n` |
| `→` | 목표 +20도 한 칸 | `p` |
| `↑` | 현재 홈을 선택 모드의 0도로 설정 | `z` |
| `↓` | 저장된 0도 목표로 복귀 | `r` |
| `Space` | 모터 정지 | `k` |
| `Esc` | 프로그램 종료 전 정지 | `k` |

## 모드 전환 절차

```text
Space
→ 모터2 정지 확인
→ 손으로 원하는 클러치 상태로 전환
→ 1(A) 또는 2(B)
→ 기준으로 사용할 실제 홈 정렬
→ 300ms 이상 정지
→ ↑
→ state=1 확인
```

모드 선택 시 이전 모드의 기준 count와 홈 번호는 무효화된다. 전원을 다시 켠 경우에도
모드를 선택하고 기준 홈을 다시 저장해야 한다. 클러치 센서가 없으므로 소프트웨어의 A/B
표시는 사용자가 실제로 맞게 고정했다는 것을 검출하지 못한다.

## 권장 시험 순서

### 클러치 A

1. Space를 누르고 링기어를 손으로 고정한다.
2. `1`, 기준 홈 정렬, `↑`를 누른다.
3. `→` 한 번 후 state=3과 최종 `output_deg`, `motor2_count`를 기록한다.
4. `←` 한 번으로 0도 복귀 오차를 기록한다.
5. `→`, `→`, `←`, `↓` 순서로 +20, +40, +20, 0도 왕복 결과를 기록한다.

### 클러치 B

1. Space를 누르고 모터2 정지를 확인한다.
2. 링기어 고정을 해제하고 캐리어를 손으로 고정한다.
3. `2`, 링기어 기준 홈 정렬, `↑`를 누른다.
4. 오른쪽 화살표에서 링기어 실제 방향과 약 20도 이동을 먼저 확인한다.
5. A와 같은 왕복 순서로 최종 count와 실제 홈 오차를 기록한다.

각 명령은 state=3 이후에 입력한다. state=2 중에는 다음 이동 명령을 넣지 않는다. 현재
오버슈트 관찰 모드는 목표를 통과하면 PWM을 0으로 만들고 관성 정지 300ms 후 실제 오차가
남아 있어도 state=3을 반환한다.

## 상태 로그

wire version 5부터 터미널은 다음 형식을 사용한다.

```text
leg[0] addr=0x10 ok=true state=3 clutch=A output_deg=22.7 motor2_count=1507
leg[0] addr=0x10 ok=true state=3 clutch=B output_deg=19.8 motor2_count=...
```

- `clutch=A/B`는 STM32에서 선택한 계산 모드이며 물리 체결 센서값이 아니다.
- `output_deg`는 A일 때 캐리어 각도, B일 때 링기어 각도이다.
- `motor2_count`는 가공하지 않은 모터2 엔코더 누적 count이다.

ESP32는 I2C 상태를 100ms마다 계속 읽지만 USB 터미널에는 매번 출력하지 않는다. 통신
정상 여부, state 또는 clutch가 바뀌면 즉시 한 번 출력하고, state=2인 이동 진행 상황만
1000ms마다 출력한다. state=3 완료와 state=4 오류는 상태 변화이므로 즉시 표시된다.
`STATUS_PROGRESS_LOG_MS`를 0으로 바꾸면 이동 중 주기 로그도 끄고 변화 시점만 출력할 수 있다.

## 남은 위험과 확인 항목

- B 모드 출력 방향 부호는 실기 미확인이다.
- 감속비 12:1의 실제 제작 공차와 백래시는 미측정이다.
- A/B 전환 과정에서 축이 움직이면 이전 기준과 연속성이 보장되지 않는다.
- 고정 PWM 70%이므로 방향별 관성 정지 오차가 다를 수 있다.
- 관찰 모드의 DONE은 홈 정렬 완료나 클러치 체결 성공을 의미하지 않는다.
- 데이터 수집이 끝나면 감속·제동과 엄격한 홈 허용오차 판정을 다시 설계해야 한다.
