## 3. 최종 핀 및 명령 매핑

| 모터 | L298N 채널 | PWM/EN | DIR 입력 | 정/역 명령 | PWM 듀티 |
|---|---|---|---|---|---:|
| 모터 1: 휠 구동 | 첫 번째 L298N A | PA6, TIM3_CH1 → ENA | PA7 → IN1, PB0 → IN2 | `i` / `,` | 70% |
| 모터 2: 선기어 | 첫 번째 L298N B | PA8, TIM1_CH1 → ENB | PB1 → IN3, PB10 → IN4 | `j` / `l` | 70% |
| 모터 3: 클러치 | 두 번째 L298N A | PA2, TIM2_CH3 → ENA | PB8 → IN1, PB9 → IN2 | `u` / `o` | 60% |

`k` 명령은 세 모터를 모두 정지한다. 세 타이머는 72MHz 타이머 클럭, Prescaler 71, Period 999로 약 1kHz PWM을 생성한다.

## 4. 통신 확인 결과

ESP32 진단 로그에서 모든 I2C 거래가 다음과 같이 확인되었다.

```text
cmd=i writeErr=0 bytesReceived=3
leg[0] addr=0x10 ok=true
```

해석:

- `cmd=<키>`: Python에서 보낸 명령을 ESP32가 수신함
- `writeErr=0`: ESP32가 STM32 주소 `0x10`에 쓰기 성공, STM32가 ACK함
- `bytesReceived=3`: STM32 상태 3바이트 읽기 성공
- `ok=true`: ESP32↔STM32 왕복 I2C 통신 정상

이 로그는 PC→ESP32→STM32 통신을 검증한다. 단, L298N 입력과 모터 출력까지 정상이라는 의미는 아니므로 모터 무반응 시 전원·드라이버·모터를 별도로 분리 진단해야 한다.

STM32 주소 `0x10`을 사용하려면 주소 점퍼 PA0과 PA1을 모두 GND에 연결한다. 두 핀을 오픈하면 내부 Pull-up으로 인해 주소가 `0x13`이 된다.

## 5. 발견한 문제와 해결

### 5-1. TIM1 설정 불일치

초기 `.ioc`에서 TIM1 CH1이 Output Compare로 설정되어 있었지만 `main.c`에서는 PWM 초기화를 사용하고 있었다. 이 경우 TIM1 PWM MSP 초기화와 클럭 활성화가 일치하지 않을 수 있다.

CubeMX에서 다음과 같이 수정하고 코드를 다시 생성했다.

```text
TIM1 Channel 1 = PWM Generation CH1
PA8 = TIM1_CH1
Prescaler = 71
Period = 999
```

재생성 후 `HAL_TIM_PWM_MspInit()` 안에 다음 코드가 생성된 것을 확인했다.

```c
__HAL_RCC_TIM1_CLK_ENABLE();
```

### 5-2. 엔코더 GPIO/EXTI 반영

- PA4: `GPIO_EXTI4`, Rising edge
- PA5: `GPIO_Input`
- EXTI4 NVIC 활성화, 우선순위 5
- `EXTI4_IRQHandler()`는 CubeMX가 `stm32f1xx_it.c`에 생성한 버전만 사용
- 방향 판별용 `HAL_GPIO_EXTI_Callback()`은 `main.c` USER CODE 영역에 유지

PC13 LED는 모터 제어에 필요하지 않아 사용하지 않았다.

### 5-3. STM32 5V 핀을 전원원으로 사용한 문제

STM32는 브레드보드 전원 모듈의 3.3V 출력으로 `3.3V` 핀에 직접 전원을 공급받고 있었다. 이 방식에서는 STM32 보드의 5V 핀이 5V 출력원이 되지 않는다. 보드의 레귤레이터는 일반적으로 5V를 3.3V로 낮출 뿐, 3.3V를 5V로 승압하지 않는다.

모터 3/L298N 측 5V 전원을 STM32 5V 핀에서 가져오던 상태에서는 모터 3이 완전히 무반응이었다. 해당 전원을 전원 모듈의 정상적인 5V 레일로 옮기자 모터 3이 동작했다.

전원 원칙:

```text
전원 모듈 3.3V → STM32 3.3V
12V 배터리     → L298N 모터전원 Vs/+12V
정상 5V 레일   → 필요한 L298N 로직 5V
모든 GND       → 공통 연결
```

L298N의 `5V-EN` 점퍼를 사용할 때는 모듈 자체에서 로직 5V가 생성되므로 외부 5V를 동시에 연결하지 않는다. `5V-EN` 점퍼와 PWM 입력용 `ENA/ENB` 점퍼는 서로 다른 역할이다.

### 5-4. 모터 2 삐 소리 및 회전 불가

증상:

- `j`/`l` 명령의 I2C 로그는 정상
- 첫 번째 L298N B채널에 연결한 모터 2에서 PWM 주파수로 추정되는 삐 소리가 남
- 모터는 회전하지 않음

처음에는 PWM 듀티 부족, 기구 걸림, L298N B채널 또는 IN3/IN4 배선을 의심했다. 정상 동작하는 모터와 교체하여 교차시험한 결과 같은 채널과 배선에서 교체 모터는 정상 동작했다.

최종 원인:

```text
기존 모터 2 자체 불량
```

불량 모터를 교체한 뒤 모터 1, 모터 2, 모터 3이 모두 정상 동작했다.

## 6. 멀티미터 없이 사용한 분리 진단법

1. ESP32 로그에서 `writeErr=0`, `bytesReceived=3`을 확인한다.
2. 각 시험 사이에 `k`를 눌러 모든 모터를 정지한다.
3. 정상 동작하는 모터를 의심 채널의 OUT 단자에 연결한다.
4. 정상 모터가 의심 채널에서 동작하면 드라이버와 제어 신호는 정상으로 판단한다.
5. 의심 모터를 정상 채널에 연결한다.
6. 정상 채널에서도 회전하지 않으면 모터 또는 기구 문제로 판단한다.

모터가 삐 소리만 내고 정지한 상태는 스톨일 수 있다. 이 상태에서는 큰 전류와 발열이 발생할 수 있으므로 1초 이내로 시험하고 즉시 `k`로 정지한다.

## 8. 후속 작업 시 주의사항

- 실제 STM32 프로젝트는 현재 저장소의 `stm32/mobility` 폴더이다. 저장소 외부의 과거 사본과 혼동하지 않는다.
- CubeMX 재생성 시 USER CODE 영역 밖의 수동 변경은 덮어써질 수 있다.
- ENA/ENB에 PWM 핀을 연결할 때 해당 채널의 EN 점퍼를 제거한다.
- 모든 제어기와 모터 드라이버의 GND를 공통으로 연결한다.
- STM32를 3.3V 핀으로 공급할 때 STM32 5V 핀을 별도 5V 전원 출력으로 사용하지 않는다.
- 모터 무반응 문제는 통신 로그만 보고 펌웨어 문제로 단정하지 말고, 정상 모터/정상 채널 교차시험으로 분리한다.
